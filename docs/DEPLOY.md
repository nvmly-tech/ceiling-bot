# Развёртывание на своём сервере

Инструкция для технического специалиста студии: как поднять бота из этого репозитория на своём сервере с нуля.
Устройство бота и все настройки подробно — в [README](../README.md); что владелец заполняет перед запуском —
в [схеме путей](Схема%20путей%20—%20владелец,%20клиент,%20менеджер.pdf).

Займёт около часа, большая часть — получение ключей в сервисах (шаг 1).

## Что понадобится

**Сервер**
- Linux с **systemd 254 или новее** — Ubuntu 24.04+ или Debian 13+ (юнит использует `RestartMode=direct`;
  на более старом systemd будут ложные алерты об остановке). Проверить: `systemctl --version`.
- 1 vCPU и **2 ГБ памяти**, если расшифровывать голосовые на своём сервере (GigaAM, шаг 6); без него хватит 1 ГБ.
  Диск — около 3 ГБ свободных.
- Вход по SSH под `root` по ключу; на сервере есть `curl` и `python3` (в Ubuntu и Debian — из коробки).
- Нужен только исходящий интернет (Telegram, Trello, нейросети). Входящих портов и домена не нужно:
  бот сам забирает сообщения у Telegram (long polling).
- По 152-ФЗ персональные данные клиентов из России нужно хранить на серверах в России — выбирайте хостинг с этим учётом.

**Своя машина для выкладки** — Linux или macOS (на Windows — через WSL) с `git`, `ssh` и
[uv](https://docs.astral.sh/uv/getting-started/installation/). Перед каждой выкладкой скрипт сам прогоняет
проверки и тесты на этой машине.

**Аккаунты** — свои у студии, на неё же и оплата: Telegram, Trello, Groq, router.cheap (шаг 1).

## Шаг 1. Аккаунты и ключи

Сохраните всё полученное — в шаге 4 это впишется в файл настроек на сервере.

1. **Бот в Telegram.** В [@BotFather](https://t.me/BotFather): `/newbot` → имя и адрес бота → получите **токен**
   (`BOT_TOKEN`). Там же можно задать описание и аватар. Если бот передаётся от исполнителя — через
   @BotFather → «Transfer ownership», токен после передачи лучше сменить (`/revoke`).
2. **Группа менеджеров.** Создайте группу, добавьте менеджеров и бота. Сразу сделайте бота **администратором с правом
   «Удалять сообщения»** — при этом Telegram может превратить группу в супергруппу со сменой id, поэтому id берите
   после. Напишите в группу любое сообщение и откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе `"chat":{"id":-100…}` — это **`MANAGER_CHAT_ID`**
   (делайте это до запуска бота на сервере: пока он работает, `getUpdates` из браузера пуст).
3. **Отдельный чат для технических сообщений** (рекомендуется) — личный чат ответственного с ботом или ещё одна
   группа; id — так же через `getUpdates` (**`ADMIN_CHAT_ID`**). Без него технические сообщения видят менеджеры.
   Так же заводится **чат владельца** (**`OWNER_CHAT_ID`**, лучше отдельная группа «владелец + бот»): туда приходят
   недельный отчёт, заявки без итога и жалобы клиентов. Без него всё это видят менеджеры в общей группе.
4. **Trello.** Создайте доску; из адреса `trello.com/b/<КОД>/…` возьмите **`TRELLO_BOARD_ID`**. Ключ
   (**`TRELLO_API_KEY`**) — на [странице Power-Ups admin](https://trello.com/power-ups/admin): новый Power-Up →
   API key; там же по ссылке «Token» выпустите **`TRELLO_TOKEN`** (права на чтение и запись). Списки «Новые запросы»
   и «В работе» и метки бот создаст сам. Дайте менеджерам доступ к доске.
5. **Нейросети.** [Groq](https://console.groq.com/keys) — ключ **`GROQ_API_KEY`** (резервная нейросеть и
   расшифровка голосовых). [router.cheap](https://router.cheap) — ключ **`LLM_PRIMARY_API_KEY`** для основной
   нейросети DeepSeek. Без ключей бот работает, но анкету ведёт по готовому сценарию, без понимания свободного текста.

## Шаг 2. Код и проверка

```bash
git clone https://github.com/nvmly-tech/ceiling-bot.git
cd ceiling-bot
./deploy/deploy.sh --check      # линтер и тесты — должно закончиться строкой «проверки пройдены»
```

До первой выкладки поправьте то, что владелец сам изменить не сможет:
- текст согласия на обработку персональных данных (152-ФЗ) — в боте его пока нет, это нужно добавить.

Название студии для приветствия владелец пишет сам в `facts.md` строкой `- Название: …` (шаг 4).

Изменения закоммитьте: выкладывается только закоммиченное (`git commit -am "…"`).

## Шаг 3. Первая выкладка

```bash
./deploy/deploy.sh root@<адрес сервера>     # адрес обязателен; выкладывается ветка main
```

Скрипт проверит код, скопирует его в `/opt/ceiling-bot`, поставит `uv` и Python 3.12 (системный Python не трогает),
установит службы systemd и создаст из шаблонов:
- `/etc/Solaris/ceiling-bot.env` — настройки и ключи (права 600, только root);
- `/etc/ceiling-bot/facts.md` — факты о студии для бота.

Пока в настройках пример вместо настоящего токена, бот будет падать при старте, а через несколько минут systemd
перестанет его перезапускать — это ожидаемо, переходите к шагу 4.

## Шаг 4. Настройки и факты о студии

На сервере откройте `/etc/Solaris/ceiling-bot.env` и впишите значения из шага 1. Описание каждого параметра —
в самом файле. Обязательно:

| Параметр | Что это |
|---|---|
| `BOT_TOKEN` | токен бота |
| `MANAGER_CHAT_ID` | id группы менеджеров (`-100…`) |
| `STUDIO_TZ`, `WORK_START`, `WORK_END` | часовой пояс и рабочие часы: ночной режим, напоминания, утренняя сводка |
| `WORK_DAYS`, `DAYS_OFF` | рабочие дни недели (`1-5` — пятидневка, по умолчанию все) и праздники (`2026-12-31`, `01-01`) |
| `TRELLO_API_KEY`, `TRELLO_TOKEN`, `TRELLO_BOARD_ID` | доступ к доске Trello |
| `GROQ_API_KEY` | резервная нейросеть и расшифровка голосовых |
| `LLM_PRIMARY_BASE_URL`, `LLM_PRIMARY_API_KEY`, `LLM_PRIMARY_MODEL` | основная нейросеть: `https://router.cheap/v1`, ключ, `deepseek-v4.1-flash` |
| `ADMIN_CHAT_ID` | рекомендуется: чат для технических сообщений |
| `OWNER_CHAT_ID` | рекомендуется: чат владельца — недельный отчёт, заявки без итога, жалобы и низкие оценки клиентов |

Строку `DB_PATH` в этот файл не добавляйте — путь к базе задаёт служба.

Затем откройте `/etc/ceiling-bot/facts.md` и замените примеры на данные студии: название (строкой
`- Название: Потолки Мастер` — бот поздоровается «Это студия натяжных потолков «Потолки Мастер»»), город, контакты, **цены,
сроки, гарантии** (сейчас там средние по рынку). Цены — цифрами со знаком ₽: бот называет клиентам только суммы из
этого файла. Этот файл владелец может править и сам в любое время — бот подхватывает изменения без перезапуска.

Запустите бота заново, чтобы он прочитал настройки (`reset-failed` снимает остановку после неудачных стартов):

```bash
systemctl reset-failed ceiling-bot && systemctl restart ceiling-bot
```

Дальше после любой правки этого файла достаточно `systemctl restart ceiling-bot`.

## Шаг 5. Проверка

```bash
systemctl status ceiling-bot                # active (running)
journalctl -u ceiling-bot -n 30             # «Bot started», «Run polling», без ERROR
```

Затем в Telegram:
1. в группе менеджеров отправьте `/status` — бот ответит состоянием: Telegram, очередь, нейросети;
2. со своего телефона пройдите анкету у бота — в Trello появится карточка, в группе — «Новая заявка»;
3. нажмите «✅ Взял в работу» — придёт панель заявки с кнопками итогов; отметьте «📅 Замер назначен» —
   карточка переедет в список «Замер», а клиенту придёт подтверждение;
4. отправьте в группе `/report` — отчёт по заявкам за неделю.

Ссылки на бота размещайте с меткой площадки — `https://t.me/<имя бота>?start=avito`, `…?start=site`:
в заявках и в отчёте будет видно, откуда пришёл клиент.

Проверить, что служба переживает сбой: `kill -STOP $(systemctl show -p MainPID --value ceiling-bot)` — примерно
через минуту systemd перезапустит зависший бот, в чат технических сообщений придёт алерт.

## Шаг 6 (по желанию). Голосовые на своём сервере — GigaAM

Без этого шага голосовые расшифровывает Groq (за рубежом). С ним — открытая модель GigaAM прямо на сервере, голос
никуда не уходит. Нужны 2 ГБ памяти на сервере и ~1,6 ГБ свободной памяти на машине выкладки (модель готовится там).

```bash
ssh root@<адрес сервера> 'apt install -y ffmpeg'
./deploy/stt/deploy_stt.sh root@<адрес сервера>   # разово готовит модель (несколько минут), выкладывает ~310 МБ
```

Затем в `/etc/Solaris/ceiling-bot.env` впишите `GIGAAM_SOCKET=/run/ceiling-bot-stt.sock` и выберите
`STT_SHADOW`: `true` — голосовое дополнительно расшифровывает Groq для сравнения качества (голос уходит и в Groq),
`false` — только GigaAM. После — `systemctl restart ceiling-bot`; в журнале: «Расшифровка голосовых: GigaAM → Groq».

## Обновления, бэкапы, наблюдение

- **Обновить бота:** `git pull && ./deploy/deploy.sh root@<адрес сервера>` (из ветки `main`). Настройки и
  `facts.md` на сервере выкладка не трогает. Выкладка не начнётся, если есть незакоммиченные изменения или упал хотя
  бы один тест. Перед заменой кода снимается бэкап базы, прошлая версия остаётся рядом.
- **Откатить обновление:** `./deploy/deploy.sh root@<адрес сервера> --rollback` — прошлая версия кода;
  с `--with-db` — ещё и база на момент выкладки (всё, что пришло после неё, пропадёт).
- **Бэкапы** базы — каждую ночь, 14 последних копий на самом сервере (`/var/lib/private/ceiling-bot/backups/`).
  Их стоит регулярно забирать на другой сервер или в хранилище. Восстановление — в начале `deploy/backup.py`.
  Упавший бэкап присылает алерт.
- **Внешний мониторинг** (рекомендуется): заведите проверку в [healthchecks.io](https://healthchecks.io) или
  аналоге и впишите её адрес в `HEALTHCHECK_URL` — узнаете, если перестанет работать весь сервер.
- **Логи:** `journalctl -u ceiling-bot`; расшифровка голосовых — `journalctl -u ceiling-bot-stt`.
- **Если группа менеджеров сменила id** (например, после выдачи боту прав администратора) — бот сам перейдёт на новый
  id и напишет в журнал, какой `MANAGER_CHAT_ID` вписать в настройки; впишите, чтобы он сохранился после перезапуска.
